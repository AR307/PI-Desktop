# PI Desktop and Android 0.16.2

## Scope

Desktop releases are published to `AR307/PI-Desktop`; Android releases are
published to `AR307/Mirrorcoding-APP`. Android source remains in this monorepo.
This release includes the tested functionality through `b6975b9d4`, with
`920b12b8e053165d343a421b3cb8ee93c50a436a` as the incorporated origin/main.

## Changes since 0.15.11

- Integrate upstream 0.16.0 and 0.16.1, including scheduled-task improvements,
  file references, model capabilities, question cards and conversation rendering.
- Add Android update checks, APK download management and system installation.
- Pair a phone once to discover computers that explicitly enable account
  sharing, including all projects, ungrouped conversations and later additions.
- Keep loaded history and downloaded attachments offline without the former
  500-message limit. Reconcile durable message changes after desktop restarts.
- Align account sharing with the MC handoff, including retrying publication,
  retaining offline computer history and reconnecting with narrower grants.
- Improve mobile login and pairing error handling and local HTML preview links.
- Read and edit BOM-marked UTF-16 logs correctly. Keep subagent edit recovery
  local to the failing delegate and report exhaustion as failure. Complete
  transcript persistence before the host shuts down.

## Packaging and delivery

- Windows x64: NSIS installer, portable EXE and portable ZIP, plus `latest.yml`
  and the installer blockmap for the existing desktop updater.
- Android: `pi-mobile-v0.16.2.apk` and generated `mobile-update.json`;
  application ID `xyz.mirrorcoding.pi.mobile`, versionCode 6, Android 7+.
- Retain the existing Android signing identity for covering upgrades. This is
  the previously distributed debug certificate, while the release APK itself
  is not debuggable. No signing key is included in the repository or assets.
- No new Windows Authenticode certificate is supplied. macOS and Linux binaries
  are not part of this Windows/Android release.
- Publish locally built packages from the dedicated release branch and tag.
  Release commits skip automatic tag builds because the inherited workflow
  requires the original upstream's macOS signing setup and publishes additional
  platforms outside this release's scope. Repository workflow configuration is
  unchanged; this release does not claim a completed cloud CI build.

The first mobile APK with in-app updates requires manual installation. Later
releases can be installed from Account. Both desktop and phone must be updated
to use the new account-sharing and durable-history contracts. MC must have its
account-sync service deployed; it does not store conversation bodies.

## Validation

The functionality candidate already passed controlled Electron/mobile-browser
acceptance (46 checks), native PiMobileQA acceptance (48 checks), and tests for
mobile account flows, shared protocol and desktop sync. These include retaining
610 loaded messages after an offline restart and restoring a narrower grant
after account sharing is revoked. See the mobile account-sync validation docs.

Final-version builds, release metadata checks and packaged startup/Android
covering-install results are recorded before publication. Controlled acceptance
does not establish production MC behavior or paid model results. The NSIS
payload is tested in isolation without replacing the user's Windows installation.
