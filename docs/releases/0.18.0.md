# PI Desktop and Android 0.18.0

## Update both paired applications

This release integrates the previously validated upstream 0.18 baseline with
MirrorCoding, Fast/Ultra, subagent controls and account-level mobile sync.
Windows packages are published to AR307/PI-Desktop. Android packages are
published separately to AR307/Mirrorcoding-APP.

The reported mobile JSON parsing error was reproduced using the installed old
Windows host against isolated synthetic data: a large transcript was cached,
then a tool message grew during a rewrite. The host accepted stale Windows
offsets and session.changes failed with an expected-value parse error. The
integrated host rejects unsupported persistent layout identities and the same
sequence returns only the changed row without editing or clearing history.

Mobile now preserves already committed delta pages and buffered live updates
when a subsequent history read fails. The conversation keeps its live controls
and model catalog, with a localized sync notice, expandable technical details
and an explicit history retry. Retrying never sends the user's prompt again.
The notice clears after recovery and stays scoped to the affected conversation.

## Assets

- Windows x64 NSIS installer, Portable EXE and Portable ZIP, with latest.yml and
  the installer blockmap for existing desktop update delivery.
- Android pi-mobile-v0.18.0.apk and generated mobile-update.json, versionCode 7,
  unchanged xyz.mirrorcoding.pi.mobile application ID and signing identity.
- No macOS or Linux binaries are supplied in this release. Existing 0.16.2
  macOS assets remain on their original release; they are not relabeled.
- No MC deployment, production account changes or paid model calls are included.

## Verification boundaries

Targeted mobile tests, five host delta regressions, TypeScript builds, sidecar,
Electron production build and optimized Rust host build passed. Controlled
Electron plus touch-browser and actual PiMobileQA Android acceptance cover the
failed-page retry, retained content, 610-row offline history, desktop restarts,
multi-computer discovery and authorization narrowing. Screenshots were reviewed.

The preceding upstream-integration run did not claim an all-green full suite:
desktop tests had 47 failures and Rust had two config-sync failures (the latter
also reproduced on unchanged upstream). These are documented in Summary.md;
targeted release acceptance is not a claim that every unrelated test now passes.
Real affected-user history and production MC behavior were not replayed.
