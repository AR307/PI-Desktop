# 0.20.2 integration and validation

## Scope

Integrate upstream 0.20.1 (2eb333723), the committed mobile redesign
(b1ab525b), storage maintenance (155141316), shared branding and the
MirrorCoding first-use agent image-generation fix. Development is isolated on
codex/sync-brand-image-release; the primary checkout is unchanged.

## Behavior

Previously the bundled image skill directed account users to GenerateImages,
which requires a manual Settings image binding. Signing in alone did not
populate that binding. MirrorCoding chat now exposes the live account tools
ListImageModels and GenerateImage instead; the skill clearly separates their
arguments from the separately configured vendor tool. Manual composer settings
are not changed. Plan/Goal retain listing only. The account catalog, provider
group and supported parameters remain authoritative.

Upstream inline attachment chips are preserved in direct image requests, but
their editor tokens are not sent as prompt text. User references are not
silently removed or supplemented with history.

## Data and release boundaries

Schema v25 combines upstream v24 worktrees and fork v24 mobile changes.
Both v24 histories receive the missing tables without resetting messages or
mobile revisions. Backups remain available; no user profile is used for tests.
The new logo is derived from the user-supplied vector, without redesigning it.

Android keeps xyz.mirrorcoding.pi.mobile with versionCode 8. Existing signing
identity is retained for upgrades. This identity is the existing development
keystore, not a newly certified production signing certificate.
