# 显式导入 Codex 历史

> **翻译说明：** 本页对应 [英文源规格](/spec/03-runtime/codex-native-import)。代码、协议字段和标识符保留原文；行为以英文源规格为准。

PI 将用户选择的本地 Codex 对话导入为独立原生会话。这是用户主动发起的一次性读取，不是同步或 ACP 会话。不会复制项目源码、凭据、权限、运行中的任务或缓存，也不会调用模型重新总结。

## 入口与本机偏好

- 侧栏标题下方、置顶对话上方的紧凑卡片与「设置 → 项目归档 → 从 Codex 导入」打开同一个向导。
- 显示卡片不扫描存储；下方列表独立滚动。
- 关闭卡片需要三选一确认。取消、Esc 和点击背景保留卡片。「仅本次关闭」由 Main 内存管理，导航和 Renderer 重载不会重置，应用重启后恢复。「不再显示」保存在本机 Renderer 偏好中。隐藏卡片不取消导入。
- 设置开关重新显示卡片并清除本次隐藏状态；导入成功不改变偏好。
- 设置搜索包含 Codex、导入、历史对话等关键词。

## 操作流程

打开向导后读取 CODEX_HOME；未设置时使用用户的 .codex。来源字段可指定目录或单个 JSONL 文件，原生选择器选择目录。候选包含活动和归档会话，支持分页、搜索、按页或项目或单会话选择，默认不全选，也不固定截断会话总数。

PI 项目组映射按来源项目身份而不是显示名称确定。Codex 保存的本地主机旧项目到 app-server 项目映射先解析为当前 SQLite 项目，再进行列表和筛选。别名只显示一次，同名但无关的项目不合并。远程主机映射不用于本地来源。非空当前会话名称用于显示和搜索；无名记录使用会话索引标题。

有序根目录、名称和各会话的实际工作目录独立保留。完全相同路径的 PI 项目组可复用；冲突根目录需显式映射。重映射保留相对工作目录后缀。缺失根目录可重新指定或明确保持未绑定。未绑定会话可阅读，但 Host 阻止续聊，直到现有移动会话流程绑定有效目录；不使用临时目录替代。来源归档状态写入来源信息，向导对新会话应用 PI 的本机归档偏好。

模型默认使用 PI 当前提供商和模型，可调整推理等级。Codex 模型和推理值仅作来源信息。续聊使用正常 PI 工具、项目指令和审批设置。

导入逐项执行并提供结果、进度、取消和失败重试。取消由 scan ID 与 batch run ID 联合识别，延迟取消不能停止新重试或恢复已取消批次。完成的会话保留。现有 import-codex-<source-id> 会话跳过，不覆盖 PI 续聊。关闭向导释放来源目录索引。

项目和目录覆盖选项默认折叠。会话行不压缩；结果使用对话框内容滚动区，不另建小滚动框。本地化警告分类在前，技术细节折叠。确认按钮位于警告上方，页脚保留审阅入口。已完成选择清除；等待审阅的项不被普通导入按钮重复提交。多项不完整会话可批量确认。

## 存储与恢复

Rust Host 负责只读 SQLite/JSONL、转换、附件持久化、项目绑定和原生会话/checkpoint 写入。Main 验证类型化 IPC 并转发，Renderer 负责交互。不新增数据库或 schema：项目映射复用 KV，恢复复用原生 transcript 压缩格式。其他导入器不变。

读取器支持独立 JSONL/Zstd、活动或归档 rollout、state_N.sqlite、thread_history_N.sqlite，以及带 ordinal/byte 边界的 history_base 链。Zstd 流式解压，不解包来源文件。物理分段身份与逻辑会话身份区分，包括首段 ID 等于会话 ID 的情况。多个分叉导入时，原生消息和工具 ID 按目标会话隔离。数据库投影及 rollout 后续记录保持源分段顺序。源数据库只读打开，投影和 watermark 在同一读事务中读取。JSONL 逐行读取，不进行头尾抽样。

可见历史和有效模型上下文分别投影：

- 可见历史保留消息、工具记录、推理摘要、错误、支持的附件；未知记录给出明确警告和原始证据。
- 有效上下文使用最新仍有效的 replacement_history、retained context 和后续有效记录，排除回滚轮次；允许摘要为空且仅保留上下文的 checkpoint。
- 原 system/developer 文本只是带标签的历史参考，不成为 PI 生效指令。旧工具结果是引用材料，不是可执行调用。未完成调用标记为中止历史。
- 稳定导入凭据锚定 checkpoint，即使来源最后一项仅有图片或未完成记录。新 PI 消息正常追加。
- 不支持或缺失上下文必须在落盘前明确确认。有可恢复消息时，allowPartialContext 保留这些消息并生成 partial checkpoint 和缺口提示。向导单条及批量确认只提供续聊导入。完全无可用上下文时解释缺失来源，要求选择完整来源后重新扫描，不静默创建空上下文。Host historyOnly 契约及已导入历史不变，但向导不提交该选项；不编造缺失内容。
- 动态工具记录保留名称、参数、输出和错误状态。计划、委派 Agent 和生图活动仅作历史材料，不恢复任务。
- 本地附件只从选定来源和项目根目录复制到 PI 现有附件存储；不远程下载。缺失文件、不支持内容和不可用原始文件表示均提示。

## 已知边界

Codex 存储是持续演进的外部格式。交错自动轮次、未来记录种类和不可用分叉段不代表能精确恢复 Codex 运行时。有可用上下文但输入不完整时，需要明确确认部分导入；不恢复运行任务、终端或子 Agent。真正缺失的 rollout 无法仅靠可见历史重建。

JSONL 输入流式读取，但单会话转换结果、有效上下文和附件数据仍在原生持久化前组装于内存。尚未验证数 GB 单会话的内存负载。

验收场景见 E2E 计划，实际证据见 [Codex 导入验证](/testing/codex-import-validation)。
