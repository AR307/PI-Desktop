# Live Voice 工作会话接入

> **翻译说明：** 本页与[英文源规格](/spec/03-runtime/live-work-session)对应。代码、协议字段和标识符保留原文；如翻译与英文事实存在差异，以英文版本为准。
>
> 状态：实施中；只有完成交付计划中的自动化和手工验证后，才能视为验收完成。Live Voice Provider 绑定与工作会话绑定是两个独立作用域。

## 目的

Live Voice 可以把有界工作请求提交到用户选择的 PI-Desktop 本地 Agent 会话。Live Provider 负责语音交流；现有 Agent Runtime 继续在会话当前模型和权限策略下执行文件、Shell、MCP、插件、Skill 和子代理工作。

## 作用域与授权

- 没有 `workTarget` 的通话仍然只是语音通话。
- 用户通过 Renderer 明确开启工作接入。Main 查询所选本地会话并生成 call 作用域的 `LiveWorkBinding`；Provider 工具请求不能指定会话、项目路径、模型、模式或权限。
- 通话的工作绑定不会随侧栏选择变化。打开其他会话只是导航；更换工作目标必须新建通话。
- 首期只接受本地 Desktop 会话。Native Pi 和远程工作会话在 Host 实现相同的作用域控制和终态事件前不可用。
- 上下文共享是工作通话中的显式选项。关闭后，意图分类器只收到当前请求和有限的工作状态元数据，不会读取会话历史消息。

## 候选请求与路由

每个 Provider 只暴露 `delegate_to_work_session({ instruction })`。Main 校验工具名和参数，冻结通话作用域，登记有界操作身份，并在意图分类或 Agent 受理前返回简短的 `received / not_started` 回执。同一 Provider 请求 ID 不会重复派发；同 ID 的不同内容会被拒绝。WebSocket 回执和工作反馈只有在 socket 写入回调成功后才报告为本地已发送；连接关闭、取消、发送错误或超过一秒写入时限均报告未送达。初始回执未送达时，不进行分类或 Host 准入。这不代表远端服务已经处理消息，也不代表用户实际听到内容。

只读的一次性分类器使用所选工作会话的配置模型，且不提供工具。严格校验后的输出进入确定性路由。普通对话和状态查询不会创建回合。只有对观察到的活动回合提出明确约束时才可 steer 该回合。明确独立的任务进入 Host 自有队列。路由含糊、目标回合过期或会话不可用时会失败关闭；steer 失败不会降级为 prompt 或 queue。结果查询读取本次通话最近一个已终态操作，或明确引用的操作，并在不启动新回合的情况下显示其有界摘要。

### 可靠性与准入身份

Main 在登记 Provider 候选请求时同步捕获活动回合。显式 `null` 表示“没有观察到活动回合”；stop 和 steer 不会改指向之后启动的回合。重复 Provider 请求 ID 会复用原操作和原观察目标。通过校验的 stop 使用预留控制分类通道并推进屏障：尚未跨过 Host 准入边界的较早写操作会被撤回；已经开始派发的写操作保持未知状态，直到只读 Host 证据完成核对。

普通新任务采用忙时拒绝准入。只有明确的 queue 意图或分类器确认独立的任务才进入 Host 队列。AgentHost 会在最终回合/队列准入边界重新检查 Main 保存的私有工作区身份与最新会话元数据。身份不匹配时会在创建 prompt 或队列条目前返回 `WORKSPACE_CHANGED`。空闲时的显式 enqueue 会要求 AgentHost 排空现有队列；恢复后仍被挂起的队列条目继续保持挂起。

分类器调用有 8 秒截止时间并接收取消信号；快照读取和单次 Host 派发等待均有时限。Host 写操作已发出但结果未知时，操作会标记为 `unknown`，只通过精确的只读身份查询核对，绝不重新提交。通话关闭会撤回尚未派发的候选请求；正在准入的操作保持未知状态，已接受工作继续由 Host 持有。UI 分别显示分类无效、分类超时、调用方撤回、回执未送达、作用域变化、Host 拒绝和派发未知。

准入摘要与终态结果彼此分开。匹配的终态事件可以解决未知准入，且不会被迟到的 ACK 降级。任务结果只关联到精确回合上的写操作；stop 操作保留自己的控制确认，并将停止目标回合单独保存在 `targetTurnId` 中，因此 stop 行不会变成任务执行/结果行。通过该控制操作发起的显式结果查询，在可能时解析到关联的写操作。Main 结果读取器会对精确终态回合进行有界历史重读，并排除子代理和工具消息。若无法读取符合条件的根 Agent 助手结果，则标记为不可用。

项目／会话查询使用 Host 元数据，最多返回 20 个带标签的选项，并附带仅在当前 call 与 binding revision 内有效的 opaque `selectionRef`。引用 60 秒后过期，不暴露项目路径或会话 ID。唯一标签的会话通过现有 Renderer 导航打开；重复标签必须在面板中明确选择。只能从已列出的注册项目创建会话，并且必须由用户点击面板操作确认。打开或创建会话都不会更改当前工作绑定。

## 现有 Host 与 Agent 的所有权

工作提交复用现有 AgentHost 和已注册的 Agent handler。Host 队列仍是唯一队列，并继续执行已有容量、顺序、投递和取消语义。语音用户消息带有可选 `voiceOrigin`，其中包含 call 和 operation ID。没有该元数据的旧消息继续有效。

停止和 abort 请求带有观察到的 turn ID，并在实际运行时所有者处校验。结束 Live 通话会关闭候选作用域和媒体，但不会取消已经被 Agent 或 Host 队列接受的工作。权限、Plan、Goal 和 AskTool 决策继续走原有 UI 和策略路径。

只有 Host 权威 turn-terminal 事件才能结算 Live 操作。消息完成、工具输出或 Provider 回复结束都不能证明工作已完成。缺少证据时保持未知；仅凭 completed 不能推断测试通过。

## UI 与当前能力边界

现有 Live 面板显示固定工作目标、有限上下文共享状态、操作 admission/execution 状态、反馈投递状态、有界路由或拒绝原因、精确终态摘要和短期项目／会话选项。面板可查看绑定会话、打开已列出的会话、在已列出的项目中新建会话、停止观察到的运行回合、取消精确队列项。创建会话沿用现有默认值，不改变当前 Live 绑定。

### 工作反馈与播报策略

Host 反馈与工作执行分开排队，最多 8 项、按身份去重并在溢出时合并。收到回执只作为 context，不自动朗读。自动状态与结果播报需同时等待 Provider 生成完成、用户停止讲话、本地播放空闲，再经过 700 ms 静默窗口和至少 3 秒播报间隔。超过 15 秒的反馈仍留在面板并降级为 context-only。静默模式只抑制主动语音播报，不停止工作；用户明确查询状态或结果时仍可播报。反馈投递失败单独显示，不能重发工作请求。

Gemini Live 与 Realtime 用 PCM 输出 credit 归还来判断本地播放队列排空。Codex 工作通话把远端音频元素接入本地 Web Audio analyser，并观察其输出采样；若监视器无法建立或 AudioContext 没有运行，自动反馈会保持等待。该信号只能证明 Renderer 在输出设备之前存在音频活动，不能证明用户实际听见；各 Provider 和设备仍需按交付计划进行实机验收。

## 隐私与资源上限

- Provider 传入的路径、会话身份、原始 IPC 操作、权限标记和任意工具 schema 都不能越过工作边界。
- 上下文投影只包含经过过滤的有界普通用户/助手文本；工具输出、附件和此前的语音来源消息都会排除。
- Live 字幕只保存在临时内存，不会作为工作会话消息插入。
- 通话取消只控制未受理候选和 Live 反馈，不作为 Agent 取消信号。
- 每通话候选身份和操作视图均有上限，并在通话结束时丢弃。已接受的队列条目和用户消息来源元数据由现有 Host 持久化机制负责。
