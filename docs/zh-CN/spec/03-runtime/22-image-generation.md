# 图片生成

> 对照[英文源规格](/spec/03-runtime/22-image-generation)。

输入区第四种任务是图片生成。主按钮循环智能体、计划、Goal、图片；三角菜单支持键盘和 Esc。进入图片模式通过现有配置退出规划；会话保留聊天模型及推理等级，生图模型、分组、参数和任务保存在 Rust 管理的 AppSettings.imageSessions。

沿用模型再分组菜单。图片模式只列授权 MC 生图能力，聊天模式列聊天路由，纯视频不列，双能力模型同时出现。分组显示账号实际倍率，动态组显示动态计费。换模型清理不支持的参数，但参考附件保留并在不兼容时阻止提交。

直接生图只发送当前提示词和明确参考图，默认一张；未选择的尺寸、比例、质量省略，不发送聊天推理参数。共享契约见[生图服务端需求](/mirrorcoding-image-generation-requirements)。

Node sidecar 使用 pi 的 createModels、createProvider 图片适配器和 generateImages，独立于 agent.prompt。主进程发临时回环绑定，注入 MC Bearer 与编码分组，协调持久附件和任务。JSON 编辑使用服务端 JSON 转 multipart 桥接。不自动更换端点、模型或组；网络、限流、服务错误不自动重放生图，输出前 401 保留既有单次刷新行为。

界面显示生成状态和停止。全局停止及换账号会取消生图。持久图片卡支持预览、保存、用作参考图；匿名 URL 下载失败或停止保留下载重试，不重新生成。停止下载保留提示词并记为取消。历史存文字元数据与附件引用，不存 base64；图片仅在明确附加时进入后续请求。失败或取消保留草稿和助手错误卡，重启恢复卡片与选择。即使没有正文，图片卡也不藏在折叠过程内。

所有执行模式可查询 ListImageModels，只有智能体或执行阶段可用 GenerateImage。工具自主选明确模型和 Provider，不覆盖用户手动选择。参考图必须指向当前会话附件，历史图仅按用户明确要求使用。纯文字模型接收元数据，工具结果展示相同卡片；停止会取消 host-local 图片工具。

受控验收使用真实隔离 Electron 输入区、IPC、Rust、sidecar、relay、HTTP 及文件附件；本地协议验证不能替代正式 MC 部署联调。
